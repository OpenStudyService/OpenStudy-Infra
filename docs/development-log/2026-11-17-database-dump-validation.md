# DB 덤프 검증과 V22 배포 준비

## 변경

작업 대상은 기존 GitOps 저장소다. GitHub의 현재 저장소 이름은 `OpenStudyService/OpenStudy-Infra`다.
Backend 커밋 `c3a45a933cd4b3210b0604a03238bfbd1c80e285`에서 V2~V22를 가져왔다.
V1은 변경하지 않았다. 22개 SQL 모두 원본 커밋과 바이트 단위로 같다.
마이그레이션 계정에 V20~V21의 뷰 생성·조회 권한을 추가했다.
앱 계정은 DML 권한만 유지한다.

기존 DB 검사 도구에 `--dump-file`과 `--report`를 추가했다.
덤프는 새 임시 MySQL에 제한된 계정으로 복원한다. 실제 DB 주소를 받지 않는다.
보고서는 데이터 값 없이 건수와 검증 결과만 기록한다.
덤프와 보고서는 커밋하지 않는다.

## 실제 MySQL 검증

첨부 파일은 MySQL 8.0.46에서 생성된 1,671,992바이트 덤프다.
MySQL 8.4.11에서 다음 두 실행을 통과했다.

| 항목 | 빈 DB 생성 | 덤프 복원 |
| --- | --- | --- |
| Flyway V1~V22 체크섬·이력 | 통과 | 통과 |
| 첫 실행의 마이그레이션 수 | 22 | 0 |
| 두 번째 실행의 마이그레이션 수 | 0 | 0 |
| 테이블 / 뷰 | 81 / 1 | 81 / 1 |
| 외래키 검사 / 오류 | 176 / 0 | 176 / 0 |
| 전체 행 수, Flyway 이력 포함 | 49 | 6,348 |
| 앱 DDL 거부 | 통과 | 통과 |
| 잘못된 TLS 호스트·CA 거부 | 통과 | 통과 |
| 적용된 V1 변경 거부 | 통과 | 통과 |

덤프의 비 UTF-8 바이트를 그대로 전달했다.
로컬 뷰의 실행 계정 지정 1건만 임시 입력에서 INVOKER 방식으로 바꿨다.
원본 파일 SHA-256은 실행 전후 같았다.
두 보고서는 `artifacts/database/`에 권한 600으로 생성했다.

저장소 표준 `./scripts/validate.sh`도 통과했다.
Terraform 모의 테스트 50개, Node 테스트 12개, bootstrap 검사 6개를 통과했다.
Python은 50개를 통과했다. 별도 native Nginx가 필요한 기존 검사 5개는 건너뛰었다.

## 한계와 후속 적용

RDS 데이터는 변경하지 않았다. Terraform apply도 실행하지 않았다.
실제 데이터 반영에는 대상 DB와 백업, 기존 데이터 처리, 세션·토큰 제거, 뷰 계정 확인이 필요하다.
기존 DB의 V8·V18 적용에는 삭제되는 AI 데이터가 있는지 확인해야 한다.
원본 덤프에는 DROP TABLE이 있으므로 기존 운영 DB에 바로 적용하지 않는다.
로그인 E2E에는 별도의 테스트 계정 비밀번호가 필요하다. 덤프의 해시와 세션은 로그인에 재사용하지 않는다.
이번 검증은 앱 기동, 운영 로그인, 업무 데이터 의미와 수동 스키마 변경의 완전한 검사를 포함하지 않는다.
