# 2026-10-30 직원 초대 SMTP 적용과 실제 수신 검증

## 배경과 결정

사용자가 Notion 최신 env의 SMTP 설정을 기존 AWS 서비스에 Terraform으로 적용하고 실제 발송을 검증하도록 요청했다.
Backend 운영 이미지는 변경하지 않았다. 이미 구현된 메일 발송기와 작업 처리를 활성화했다.
AWS RDS·prod 프로필·기존 도메인을 유지했다. env의 로컬 DB·관리자·미리보기 설정을 가져오지 않았다.

## 구현

- Gmail `smtp.gmail.com:587` STARTTLS와 인증서 호스트 검증을 사용한다.
- 계정·비밀번호는 기존 Parameter Store에 표준 SecureString 2개로 저장한다. 별도 AWS 서비스를 추가하지 않았다.
- Terraform ephemeral 입력과 `value_wo`를 사용한다. 비밀번호가 계획 JSON·state·backup에 없는 것을 검사했다.
- ECS 실행 역할에는 두 파라미터의 조회만 추가하고 앱에는 SSM ARN으로 주입한다.
- SMTP 연결·읽기·쓰기 제한은 5초·10초·10초다. SMTP 디버그 출력을 끈다.
- 수락 링크는 기존 도메인의 `https://openstudy.duckdns.org/invitations/accept`로 생성한다.
- 시작 시 SMTP 연결·인증을 검사한다. 반복 health 점검은 Gmail에 반복 로그인하지 않도록 메일 점검을 제외한다. 실제 발송 오류는 발송 작업 상태와 재시도에서 처리한다.
- ECS 태스크 정의는 새 정의를 먼저 생성한다. 기존 정의는 서비스 교체 후 정리한다.

## 실제 적용

먼저 발송을 끈 상태로 인증을 검증했다. 첫 적용은 3개 생성·2개 변경·1개 교체 삭제다.
다음으로 발송을 활성화했다. 두 번째 적용은 1개 생성·1개 변경·1개 교체 삭제다.
EC2·RDS·보안 그룹은 변경하지 않았다. 외부 587 연결은 기존 규칙에서 허용한다.
비밀값 버전 변경 시 ECS도 새 값을 읽도록 태스크 환경에 갱신 번호를 포함했다.
최종 ECS 태스크 정의는 4번이다. 서비스는 정상 실행 중이다. 최종 Terraform 계획은 `No changes`다.

## 발송과 수신 검증

- 이전 검증용 example.test 주소의 초대 1·2번은 활성화 전에 업무 API로 취소했다. 두 작업은 발송 생략 상태다.
- 사용자가 수신 주소 질문에 제공한 env의 Gmail 주소를 사용했다. 해당 계정 자신에게 초대 1건을 생성했다.
- 초대 ID 3, 이름 `SMTP 발송 검증 1030`, AWS 검증 지점 2, 일반 직원 역할로 생성했다.
- Backend 컨테이너에서 실제 RDS를 조회했다. 초대는 `PENDING`, 발송 작업은 `SENT`, 시도는 1회다.
- AWS 직원 관리 화면도 `발송 완료`를 표시한다.
- 기존 Gmail 커넥터는 다른 계정이다. 검증 계정의 INBOX에 읽기 전용 IMAP으로 접속했다.
- `2026-10-30 15:01:38 KST`에 `OpenStudy 직원 초대` 메일 수신을 확인했다.
- 메일 본문의 검증 이름과 실제 HTTPS 수락 주소, 초대 토큰 형식을 확인했다. 토큰과 원문은 기록하지 않았다. 읽음 상태를 변경하지 않았다.

SMTP 전용 Terraform 6건과 env 분리 도구 3건을 통과했다. 기존 Infra 전체 검사도 통과했다.

## 범위

실제 발송과 수신까지 검증했다. 수락·관리자 승인·직원 활성화는 수행하지 않았다.
실제 수신 주소와 비밀번호·초대 토큰은 커밋하지 않았다. 화면 캡처는 사용자 로컬 검증 폴더에만 저장했다.
메일 발송은 활성 상태로 유지했다. 기존 평일 11시 시작·매일 18시 중지 스케줄도 유지한다.
