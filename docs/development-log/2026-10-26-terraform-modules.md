# AWS Terraform 기능별 모듈 분리

작업일: 2026-10-26 (Asia/Seoul).
관련 이슈: [#5](https://github.com/OpenStudyService/OpenStudy-Infra/issues/5).
기준 소스: `5998d73f36912145bad23e1d51287537ecebb2bf`의 PR #4 브랜치.

## 문제와 결정

기존 `terraform/aws`는 기능별 파일로 나뉘어 있었다. 리소스는 모두 같은 루트 구성에서 직접 선언했다.
네트워크·서버·DB·앱·정적 웹·운영 스케줄을 여섯 하위 모듈로 분리한다.
실행 위치와 상태 파일은 유지한다. 기존 기능의 코드 위치와 연결을 정리하는 작업이다.
변경 전·후 구조와 모듈별 담당은 [모듈 안내](../terraform-modules.md)에 정리했다.

## 구현 내용

- `terraform/aws/modules.tf`에서 여섯 모듈을 연결한다.
- 공통 값·템플릿 렌더링·AWS 조회·Lambda 압축 준비는 루트 구성에 둔다.
- 기존 입력 선언 35개와 출력 이름 19개를 유지한다.
- `moved.tf`에 기존 리소스 선언 55개의 이전 주소와 새 주소를 기록한다.
- 기존 오류 차단 조건은 유지한다. Terraform의 `expect_failures`는 하위 모듈 내부 주소를 받을 수 없어 해당 검사 8개를 각 모듈의 테스트로 옮겼다.
- 하위 모듈의 개별 검사도 루트 AWS 제공자 잠금 파일과 같은 버전을 사용한다.
- DB 모듈에 서버 변경을 추적하는 Terraform 내부 기록 1개를 추가한다. 서버 변경 시 DB 적용 작업을 다시 실행하는 기존 연결을 보존한다. AWS 리소스는 아니다.

ECS 클러스터는 EC2 호스트 준비와 함께 `server`에 둔다.
ECR·앱 태스크·앱 서비스는 `applications`에 둔다.
사용하지 않는 리소스 출력은 내보내지 않는다. DB 비밀번호는 모듈 출력에 포함하지 않는다.

## 변경 전 상태를 사용한 검증

`check-terraform-module-moves.py`는 과거 소스를 Git에서 읽어 임시 사본을 만든다.
모의 제공자로 이전 상태를 만든 뒤 같은 상태에 새 모듈 구성을 연결해 계획을 비교한다.
SQL·템플릿·웹 소스는 같은 현재 파일을 사용해 Terraform 구조 변경만 비교한다.
실제 AWS 상태나 자격증명으로 계획을 만들지 않는다.

```sh
python3 scripts/check-terraform-module-moves.py \
  --base-ref 5998d73f36912145bad23e1d51287537ecebb2bf
```

| 검사 항목 | live 모드 | mock 모드 |
| --- | --- | --- |
| 기존 AWS 리소스 인스턴스 유지 | 62개 | 61개 |
| 공개 출력값 유지 | 19개 | 19개 |
| AWS 생성·수정·교체·삭제 | 모두 0건 | 모두 0건 |
| 새 Terraform 내부 연결 기록 | 1개 | 1개 |

두 모드를 합쳐 55개 리소스 선언의 이동을 모두 확인했다.
EC2·RDS 식별자도 유지됐다. 실제 배포 검증이 아닌 모의 상태의 비교 결과다.

검증 도구의 초기 실행은 과거 사본의 파일 목록과 입력값 지정이 빠져 실패했다.
이후 로컬 provisioner가 모의 제공자에서도 실행되는 점을 확인했다.
초기 로컬 명령은 Node 버전 검사에서 중단됐고 AWS 배포는 실행되지 않았다.
검증용 사본에서 provisioner를 모두 제거하고 유효한 모의 ARN을 지정한 뒤 위 검사를 통과했다.
Lambda 압축을 모듈 안에 두면 의존성 때문에 해시가 미확정되어 계획에 불필요한 수정이 생겼다.
압축 준비를 루트로 옮겨 변경 0건을 확인했다.

## 기능 검사

Terraform 1.16.6으로 `./scripts/validate.sh`를 실행한다.

- Terraform 모의 검사 47개 통과: AWS 루트 26개, 서버 모듈 4개, 정적 웹 모듈 2개, 앱 모듈 2개, Cloudflare 5개, 선택형 Frontend 8개.
- Bootstrap 구문·크기 검사 6개 구성 통과.
- Node 검사 12개 통과.
- Python 48개 중 43개 통과. Nginx 실행 파일을 지정하지 않아 CORS 검사 5개는 건너뛰었다.
- 기존 입력 선언의 기본값·자료형·검사문과 공개 출력 이름을 기준 소스와 대조했다.

## 적용 범위와 후속 작업

이 변경은 기존 AWS 계정·리전·DuckDNS 도메인·리소스 이름·예산·백업 정책을 유지한다.
Cloudflare와 선택형 CloudFront 구성의 리소스는 이동하지 않았다.
DB V1~V3 초기 적용 PR #4 위에 쌓은 후속 구조 정리 PR이다. 병합 순서는 #4 이후 이 PR이다.
PR #4의 중복 Flyway 실행 차단도 앱 모듈로 옮기고 검사했다.
실제 AWS 조회 계획·적용, RDS 변경, 프론트 게시와 PR 병합은 수행하지 않았다.

실제 적용 전 기존 위치에서 `terraform init`과 계획을 실행해 운영 상태의 차이를 검토한다.
모의 결과만으로 실제 운영 계획의 변경 0건을 단정하지 않는다.
