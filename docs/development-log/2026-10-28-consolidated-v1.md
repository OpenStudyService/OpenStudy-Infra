# 통합 V1 초기 DB 적용 준비

## 배경과 결정

Backend PR #53은 운영 앱의 Flyway를 끄고 통합 V1을 SQL 정본으로 지정했다.
기존 PR #4의 구형 V1~V3은 더 이상 최신 Backend의 초기 적용 기준이 아니다.
2026-10-28 AWS 계정 118167167440의 서울 리전을 읽기 전용으로 조회했다.
RDS 인스턴스와 클러스터는 없었다. 기존 `openstudy-prod-mysql`은 2026-10-24 01:05:49 KST에 삭제 요청이 성공했다.
실제 DB가 없어 당시 Flyway 이력과 체크섬은 조회하지 못했다.

빈 DB는 Backend 통합 V1을 적용한다. 과거 이력이 있는 DB는 별도 전환 절차가 필요하다.
기존 이력의 체크섬을 수정하거나 자동 clean, repair, baseline을 사용하지 않는다.

## 구현

- Backend 병합 커밋 `f36e4519848564b17dd8a795a36dfbb63e83eebb`의 V1 SQL을 파일명과 내용 그대로 복사했다.
- SQL SHA-256은 `497e4b4d3827e9051e8c48adb2b94bece307762482891666a414ff25b1a24403`이다.
- 기존 V1~V3 사본을 실행 경로에서 제거하고 Terraform 검사와 문서를 새 기준으로 바꿨다.
- Backend 운영 프로필과 임시 DB에 필요한 테스트 전용 설정을 로컬 검증에 추가했다.
- 운영 환경에서는 Infra가 Flyway를 실행하고 Backend는 비활성화한다.

## 검증

- 격리 MySQL 8.4.11과 Flyway 11.20.2에서 V1을 적용했다. 업무·세션 테이블 65개, 이력 테이블 1개, 성공 이력 1개를 확인했다.
- 재실행 시 추가 적용은 없었다. Flyway validate와 적용한 V1 변경 거부를 확인했다.
- 잘못된 TLS 호스트와 인증서가 거부됐다. Backend PR #53의 JAR이 운영 프로필과 Flyway 비활성 설정으로 스키마 검사 후 기동했다.
- Terraform 47개, Node 12개, Python 43개가 통과했다. Nginx 검사 5개는 실행 도구가 없어 건너뛰었다.
- 임시 DB와 테스트 네트워크는 정리했다. 실제 AWS 리소스는 생성하거나 변경하지 않았다.

## 남은 작업

- 앱 계정과 마이그레이션 계정을 분리하고 권한 및 시크릿 전달을 구성한다. 현재 Runner는 RDS 관리자 시크릿을 사용한다.
- 실제 AWS 구축에는 비용이 발생할 수 있다. 사용자가 요청한 비용 조건에 따라 이번 작업은 로컬 검증까지만 수행한다.
- 실제 RDS 적용과 OWNER 초기화, 로그인·세션 검증은 수행하지 않았다.
