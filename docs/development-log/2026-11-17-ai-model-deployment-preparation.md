# 2026-11-17 AI 모델 배포 준비

## 배경과 범위

사용자가 `models.zip`과 Qwen 설정 안내를 전달했습니다.
작업 대상 확인 후 현재 GitOps 저장소에서 배포 준비를 진행하도록 결정했습니다.
작업 브랜치는 `chore/2-ai-deployment-preparation`입니다.
기준 커밋은 이 저장소의 `origin/main`인 `05a5ed9`입니다.
Backend의 현재 계약은 `c3a45a9`에서 읽었습니다. Backend 소스는 수정하지 않았습니다.

## 결정과 이유

Backend 배포 계약 11절에 따라 모델을 이미지에 넣지 않습니다.
기존 비공개 배포 버킷과 EC2의 SSM 경로를 사용합니다.
첨부 모델은 x86_64용이므로 기존 AMD64 예산 프로필에만 연결합니다.
Qwen 키는 ECS의 기존 SSM SecureString 참조 방식으로 전달합니다.
실제 키는 이번 준비 작업에 필요하지 않아 스크린샷에서 복사하지 않았습니다.

## 구현

- `install-ai-model.py`가 ZIP 항목, 파일 크기, 고정 SHA-256을 검사합니다.
- 경로 조작, 중복 항목, 심볼릭 링크, 누락·손상 파일은 거부합니다.
- 임시 디렉터리에서 검사를 끝낸 뒤 최종 경로로 한 번에 이동합니다.
- 기존 정상 설치는 재사용합니다. Docker가 만든 빈 경로는 완성된 디렉터리로 교체합니다.
- 파일이 들어 있는 비정상 기존 경로는 보존하고 오류를 반환합니다.
- `ai_model_archive_path`로 비공개 S3 업로드와 SSM 모델 설치를 선택합니다.
- 압축 파일 해시를 S3 객체 키와 호스트 경로에 포함합니다.
- ECS 서비스 갱신은 모델 설치 성공을 기다립니다. 모델은 읽기 전용으로 마운트합니다.
- `enable_ai_live`가 두 모델 모드를 `live`로 맞추고 Qwen 접속 설정을 주입합니다.
- 키 누락, 평문 키, ARM 호스트, 관리 환경 변수 충돌은 계획에서 거부합니다.
- 기본값은 비활성입니다. 기존 IAM 정책은 AI 비활성 시 원래 형태를 유지합니다.
- 사용 절차와 후속 배포 조건은 [AI 모델 배포 준비](../ai-deployment.md)에 기록했습니다.

## 실제 첨부 파일 검증

원본 ZIP과 내부 파일 3개의 SHA-256이 전달 계약과 일치합니다.
모델 차원은 매니페스트 기준 384입니다.
검증한 ZIP과 추출 파일은 Git에서 제외하는 `artifacts/ai-model/`에 보관했습니다.
같은 경로의 `verification.json`에 파일별 크기와 SHA-256을 기록했습니다.
이 검사는 파일 무결성 검사입니다. ONNX 추론 또는 실제 Qwen 호출 검사가 아닙니다.

## 자동 검증

`./scripts/validate.sh`가 종료 코드 0으로 끝났습니다.

| 검증 | 결과 |
| --- | --- |
| Terraform 1.16.6 형식·validate | 3개 스택 통과 |
| AWS Terraform 모의 테스트 | 45개 통과. AI 신규 8개 포함 |
| Cloudflare Terraform 모의 테스트 | 5개 통과 |
| Frontend Terraform 모의 테스트 | 8개 통과 |
| Node 테스트 | 12개 통과 |
| Bootstrap 구문·크기 검사 | 6개 구성 통과 |
| Python 테스트 | 61개 중 56개 통과, 5개 건너뜀. AI 신규 11개 통과 |
| Git diff 공백 검사 | 통과 |

건너뛴 5개는 `TEST_NGINX_BINARY`가 필요한 기존 CORS 테스트입니다.
기존 HTTP 오류 모의 객체에서 Python ResourceWarning이 나왔지만 실패는 없습니다.
초기 Terraform 실행은 샌드박스의 공급자 통신 제한으로 실패했습니다.
같은 고정 버전으로 제한 밖에서 모의 검증을 실행해 통과했습니다.
첫 회귀 검사에서 IAM의 단일 Resource 형식 변경을 발견했습니다.
AI용 문서 권한을 별도 Statement로 추가해 기존 정책과 검사를 보존했습니다.

## 배포 상태

실제 AWS 계획·적용, S3 업로드, SSM 비밀값 등록, ECS 배포, Qwen 호출은 실행하지 않았습니다.
사용자 요청에 따라 작업 브랜치의 변경을 커밋·push하고 `main` 대상 PR로 제출합니다.
PR 병합과 운영 배포는 이번 요청 범위에 포함하지 않습니다.
기존 Gateway·Service 이미지 조건과 DB 전환은 별도 배포 작업으로 남아 있습니다.
현재 작업으로 Infra #2 또는 Backend #97의 전체 인수 조건을 완료한 것은 아닙니다.
